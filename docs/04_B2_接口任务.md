# 新版A2真正实现：代码组独立交付任务（不由教程原型替代）

**停靠位置**：将新版实现放入 `verifier_a2/` 或独立仓库；不可覆盖原IEEE Access 107/16冻结实现。`tools/prototype_contract.py` 是培训逻辑，原则上不直接复用为正式验证器。

1. 对照论文V1.6、S15、S20、原实现冻结哈希，出一页“规范→输入字段→执行步骤→失败码”契约表。
2. 约定输入：release_id、service_id、cutoff t、audit_at t_a、原始信号全集证明、disposition有效状态历史、Finding和源发布归因、Requirement准确修复周期、目标发布独立闭合证据；明确数据来源和可信边界。
3. 约定输出：`historical_closed_as_of`、`audit_closed_as_of`、`machine_decision`(CLOSED/OPEN)、`evidence_status`(PENDING/OPEN/NFI/NOT_APPLICABLE)、稳定失败码。避免混用事实状态和二值机器决策。
4. 同一历史快照存储不可变digest；追加Finding和目标证据后只允许审计结果变化。
5. 按六个必要边界跑测试：无Finding且可证完整、缺Finding→Requirement、源发布归因不明、目标未到期、目标到期缺验证、目标完成且旧历史不改写。
6. 比较H与T的确切关系，并记录空集义务何时具有可核验观察范围。
7. 新增版本与旧冻结包分支隔离，所有输出SHA-256归档；不要将原107/16宣称为新接口测试。
8. 正式E1独立Oracle必须先冻结规范与预期；代码组不得看到盲评标签后回写答案。
